# Leon Xu

**Building AI products, from a concrete problem to a working prototype.**

I’m interested in the early decisions that shape a product: whose problem to solve, what the smallest useful experience looks like, and what evidence would justify the next step. I use code to explore those decisions through agent systems, human–AI interaction, and data tools.

I’m looking for **Founder’s Office / founding-team** and **Product / Product Engineering** internships at AI and intelligent-hardware startups. I’m also interested in product development and the path from prototype to adoption.

## Selected work

Each repository explains the intended experience, implementation, verification path, and current limits. These are prototypes and reference implementations; test results are separate from customer adoption.

| Project | Product question | What to inspect |
|---|---|---|
| [**CLAW — education agent**](https://github.com/Leonxu6/school-claw) | How can parents and teachers use a shared assistant while keeping each child’s records appropriately scoped? | Role-scoped reads and writes, persistent learning observations, and an OpenClaw integration harness. |
| [**DataSteward**](https://github.com/Leonxu6/datasteward) | What controls are needed before an AI agent can help with operational data? | A synthetic manufacturing-data workflow, governed tools, access policies, action previews, and rollback. |
| [**Cyber-Superego**](https://github.com/Leonxu6/wakeupagent) | How could a desktop assistant notice a distraction without making its own interventions disruptive? | Local visual perception, contextual classification, agent memory, and opt-in desktop actions. |
| [**Wren**](https://github.com/Leonxu6/wren-agent) | How can an AI character maintain continuity while preserving boundaries and a distinct voice? | A Telegram relationship-simulation prototype with separate decision and speech stages, memory, and an offline evaluation harness. |
| [**Minecraft AI Companion**](https://github.com/Leonxu6/Minecraft_player) | How can a game companion combine task execution with conversation? | Separate task and conversation agents connected to a Mineflayer control bridge. |

## What I bring to a small team

- **Problem framing:** connect a user scenario to a concrete product scope and a testable prototype.
- **Hands-on implementation:** work across Python, TypeScript, agent orchestration, APIs, and data workflows.
- **Product tradeoffs:** make privacy, permissions, failure behavior, and human control part of the experience.
- **Evidence and iteration:** distinguish what is implemented, what has been tested, and what still needs real-world validation.

I’m continuing to learn how to turn technical prototypes into products people choose to use. The repositories above are the clearest record of that work so far.
